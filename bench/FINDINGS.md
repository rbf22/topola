# Benchmark findings, issues, and action queue

Tracking document for the corpus benchmark workstream (PCBench +
freerouting fixture subset). IDs are stable — reference them in
commits/reports (e.g. "I3: adaptive cap"). Statuses:
`open` · `in-progress` · `mitigated` (partial fix, measurable gap
remains) · `done` · `wontfix`/`fixture` (root cause is corpus data,
not the engine).

## Method context

- Corpus: 31 vendored boards — 16 freerouting fixtures, 15 PCBench
  conversions (`bench/corpus.tsv`). Deterministic runs:
  `--deterministic --max-steps N --seed S`.
- Phase-1 sweep: 341 runs = 31 boards × 11 single-flag configs, all
  on the pre-fix binary — a consistent baseline.
- Post-fix A/B: 12 representative boards × {baseline,
  `--surgical-ripup`, `--surgical-ripup --per-ratline-steps 3000`}
  on the rebuilt binary (obstacle accumulation + per-ratline cap).
- Budgets are `~150 × ratlines` clamped 30K–150K steps. Note F15:
  step counts are a poor wall-clock proxy.

| F2 | The effort sink is geometric, not search-ordering: `path_reconstruct ≈ visit_navnode` (17–75K/board); ~43% of `step_to` draws error out; rework undoes ~50% of drawn steps. | metrics logs, e.g. wavefolder `infringe 22941x`, `cands 275351`. |

| F7 | Blocker composition explains F6: 66–82% of blocking obstacles are *fixed* geometry (`FixedDot`/`FixedSeg` — pads, board features), not routed bands. modular_bus 483/728 fixed; wavefolder 656/797 fixed. | `--blockers-csv` on rebuilt binary. |
| F8 | Two failure classes: **search-sensitive** boards have 0 always-fail nets (contribution, logicboard, prog_rig, smoothieboard, gp8b, modular_bus — every net routes under *some* config); **structural-core** boards have a hard immune set (issue208 284/298, vc4000 93/108, tairakb 45/55, myboard 43/54, fq101 29/68 always-fail). | per-net × per-config unrouted matrix. |
| F9 | issue208 is a 13-connector backplane: multi-pin power/ID nets (12-pin chains) plus ~280 two-pin connector nets competing for identical corridors — congestion collapse by construction. | netlist inspection. |
| F10 | lvds2tmds panics in 7/11 phase-1 configs: `spade::delaunay_core::TriangulationExt::locate_with_hint_option_core` — "Failed to locate position" inside `PrenavmeshBases::prenavmesh_with` → `navmesh_in` → `start_routing_ratline`. | F11 | Wall-clock vs steps mismatch: 200K steps on wavefolder ran in ~1.2s. Sweep budgets (30–150K ≈ 0.2–1.2s) may under-measure configs — but F4 shows bigger budgets plateau, so the binding constraint is mostly not budget size. | timing runs. |

| F14 | Sibling of F5 found in review: `probe.rs` `terminal_blocker` zipped last-step `ghosts` with `obstacles().first()` — after accumulation, "first" meant earliest-seen, pairing mismatched data. | F15 | Search churn measured inside `step_to`: e.g. wavefolder `infringe 22941x (177.6ms)`, `cands 275351` — candidate evaluation dominates; a cheap necessary-condition prune before full draw attempts could cut most of it. | metrics internals dump. |
| F16 | lvds2tmds panic root cause: `Triangulation::intersects_constraint` resolved endpoints by *position* → `LineIntersectionIterator::new` → `get_first_intersection` → `locate_with_hint_option_core` walked forever locating `(166500,-82124.99999999999)` (float-noise pad coords). Fixed by driving the same predicate through `can_add_constraint` on vertex *handles* — `new_from_handles` never locates; position path kept as fallback for absent handles. | full backtrace + per-phase bisection; regression test `autoroute_external_lvds2tmds_does_not_panic`. |
| F17 | `--preprobe` finds blockers but seeding doesn't convert: wavefolder 319, modular_bus 149, sensors 355 blockers seeded → identical unrouted counts. issue208 found only 12 blockers/422 probes — at relaxed clearance corridors exist individually; failures are clearance-margin/collective-density, not topological. | A2 A/B, seed 0, corpus budgets. |
| F18 | Corpus-wide blocker composition (42-board census, `scripts/blocker_census.sh`): fixed geometry is 60–100% of blockers on every board that reports events. Rip-up-amenable minority (routed% ≥20): sizif128 40%, modular_bus 35%, avionics_hub 26%, tinytracker 26%, cnh_tester 24%, tairakb 23%, myboard 21%. Pure-geometry boards (fixed ≥95%): issue208 100%, logicboard 99%, gp8b 99%, fq101 99%, j2_reference 98%, wavefolder/smoothieboard/vc4000 ~96%. | `bench/out/blocker-census/` — capped mode (`--per-ratline-steps 3000`) gives coverage; baseline records ~0 events on starving boards. |
| F19 | Blocker attribution only fires on *terminated* searches: at corpus budgets most boards record 0–3 events baseline because the runaway search eats the budget mid-`step()` (F3 mechanism at scale). Capped mode terminates each search → events flow — but only ~budget/cap events. **blockers.csv underreports failure diversity at any finite budget.** | census baseline vs capped event counts. |
| F20 | Cap-3000 corpus-wide completion effect (vs baseline, same seed): mostly ±0–5, but opamp_bench_supply 61→105 (−44, worst), lvds2tmds 24→29, fq101 350→380, issue208 415→422; gains: cnh_tester 163→155, uprogrammer 145→137, linepcb 154→166 (worse). Net-negative overall — fixed cap confirmed wrong-shaped (I3). | census unrouted columns, seed 0. |
| F21 | Escape-vs-corridor census (`--suggest-shifts` channels, `scripts/escape_census.py`): corpus-wide 2266 escape-region vs 4913 corridor blockers (**32%/68%**) — corridor congestion dominates but escapes are a real minority. Second axis: boards split into *geometrically blocked* (issue208, sizif128, board_unrouted, avionics_hub, cnh_tester, vc4000 — most unrouted channels walled) vs *unblocked-but-unrouted* (contribution 3/947, logicboard 3/916, tairakb 0/172, modular_bus 3/60 — corridors geometrically open, nets still fail) — matching F8's structural vs search-sensitive classes. | `bench/out/escape-census/`, seed 0 baseline. |
| F22 | Stale `band_termseg` marks are a real reachability bug: the mark lives on ratsnest edge weights outside the edit record, so undoing a band's creation leaves it set. `probe.rs::unrouted_ratlines` trusted the mark → post-undo probes (and any post-rip-up re-probe) silently skipped ratlines whose bands no longer existed. Fixed by consulting `board.band_between_nodes` — the same undo-consistent registry `planar_autoroute` uses for its skip check. Regression test: `test_probe_channels_after_undo_still_finds_ratlines`. `planar_reconfigurer` already avoided the mark for the same reason (its comment documents the hazard). | code audit after I14 probes showed marks survive undo-all (astable: 16 stale). |
| F23 | I4 candidate-prune measured: an AABB precheck in `overlapees_among` (inflated intersector bbox vs the candidate's stored R-tree envelope — exact necessary condition since `inflate(m)` grows every shape's bbox by exactly m/side) rejects only **0.2–0.4%** of candidates (wavefolder 397/189k, contribution 2074/508k). The envelope query's largest-clearance inflation is already tight on uniform-clearance boards; the residual candidate volume is legitimately in-envelope work, not over-admission. Gate kept (strict improvement on class-diverse boards, ~zero cost) but it is not the churn lever — F2's real sink is rework/undo volume. | metrics A/B on wavefolder + contribution, post-change binary. |
| F24 | **Slot↔ratline aliasing in surgical rip-up — the real I14 root cause**: `PlanarAutorouteExecutionStepper`'s `layout_edits`/`board_data_edits`/`slot_ratlines` are append-only in *attempt order*, but the rip-up slot drop mapped ratlines to slots via `configuration.ratlines.iter().position(uid)`. Reconfigurations reorder/insert ratlines (`planar_reconfigurer::insert_ratline_after`, emit orderings, protected-pin front-loading), so current position ≠ recording slot — in debug this fired `edit slot N must hold the ripped ratline's edits`, in release it silently dropped the *wrong* slot's edits into the merged record, corrupting the pending edit. Fixed by locating slots value-keyed through `slot_ratlines` (the authoritative ratline→slot map) and dropping *all* slots matching a ripped ratline. **Verification**: astable `case_2` replay-2 went from 10+ min of reconfigure churn leaving 26 unconnected → completes fully routed in ~2.6s under the strict completion assert. Note: the positional `backtrace_to_index` callers (`reconfigure`, `install_tail_configuration`) still assume the emit contract (reorders only the un-attempted tail / survivors keep prefix order) — worth a dedicated audit if ordering divergence resurfaces. | astable `case_2` panic `slot 4: EdgeIndex(15) vs EdgeIndex(1)` under replay-2's divergent rip-up sequence; post-fix strict assert green. |
| F25 | **Whole-attempt obstacle union regresses surgical rip-up — reverted**: `RouteStepper.obstacles` was changed from per-step overwrite (HEAD: last probe's report, empty on the terminal `NotFound` step → rip-up driven by clinch detection) to a deduplicated union across all probes. The union makes every probed obstacle a blocker candidate — but a *probed* obstacle is not a *blocking* one: rip-ups tore out bands the frontier merely grazed, cascading into 36 unconnected ratlines on `tht_db25_surgical` and failures on `led_matrix_surgical` (both cases). Bisected: HEAD+route.rs-only reproduces; union reverted, `step_limit` machinery kept. Lesson: blocker attribution inputs must model *terminal* blockers, not search history. | unilayer surgical suite: 3 tests × 2 cases red under union, all green after revert. |
